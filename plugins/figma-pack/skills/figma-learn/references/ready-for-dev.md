# Макет, готовый к разработке: правила для дизайнеров

Этот лист — для дизайнеров Mbank / MDigital. По нему фрейм хорошо читается через Figma MCP, наш генератор (spec@1 → Figma и код) и `figma-learn`, а фронтендер получает код из кита, а не набор абсолютных прямоугольников. У каждого правила — зачем оно и чем проверяется.

Чем проверяем:

| Проверка | Где | Когда |
|---|---|---|
| `structure-audit.js` | скилл `figma-structure`, запуск через `use_figma` | на странице перед передачей; цель — 0 ошибок |
| `lint-design.js` (southleft, MIT) | `figma-structure/references/vendor/` | контраст, размеры целей, токены, auto layout |
| `figma-learn analyze` | этот скилл, REST API | раз в месяц по всем файлам команды: оценка 0–100 на файл, `report.md` |

Оценка готовности в `report.md` складывается так: auto layout 25, переменные и стили 25, имена слоёв 15, экземпляры против detached 15, Ready for dev 10, без `[draft]` 10. 80+ — A (можно отдавать), 60–79 — B, ниже 60 — C.

## 1. Auto layout у каждого контейнера

- Каждый фрейм с двумя и больше детьми — auto layout: направление, gap, padding. Group не используем.
- Абсолютное положение — только для наложений: бейдж на аватаре, крестик, FAB.
- Ширина блоков — Fill, высота — Hug; размеры фиксированные только там, где они правда фиксированы (sideMenu 280, ячейки таблицы).

**Зачем.** MCP (`get_design_context`) и наш разбор превращают auto layout во flex/grid с gap и padding. Без него код получает `position: absolute` и пиксели, а адаптив пропадает.
**Проверка.** `structure-audit.js`: `no-autolayout`, `group`; `lint-design.js`: `no-autolayout`; `figma-learn`: доля «auto layout у контейнеров».

## 2. Переменные вместо значений

- Цвета заливок, обводок и текста — только переменные `2.theme` (или стиль). Не примитивы, не hex, не `brand/kassa/*` напрямую: бренд меняется режимом `1.brand` на фрейме экрана.
- Отступы, gap и радиусы — переменные (`spacing/*` в вебе и CRM, `paddings/default/*` в мобильном ките, `radius/*`), включая 0. Шаг сетки — 4 px.
- Текст — текстовые стили кита (`font/Heading/h4`, `font/Body/s` …).

**Зачем.** Переменная доходит до кода именем токена (`text/muted` → `text-muted-foreground`), hex — только числом, которое не переключит тему и бренд. Линтер в коде такой hex всё равно отклонит.
**Проверка.** `structure-audit.js`: `raw-color`, `raw-spacing`, `raw-radius`, `off-grid`, `no-text-style`; `lint-design.js`: `hardcoded-color`, `no-text-style`, `token-misuse`; `figma-learn`: «Гигиена токенов» и таблица сырых hex с ближайшим токеном.

## 3. Компоненты кита — экземплярами

- Кнопки, поля, таблицы, sideMenu, topHeader, бейджи, пагинация — экземпляры из библиотек Web components / CRM UI KIT / Mobile KIT.
- Не отсоединяйте (detach). Если без detach не обойтись — только верхний уровень, слой называется `<имя> (detached)`, и это пункт в бэклог кита: напишите, чего не хватило.
- Повторяющиеся строки, карточки, пункты списка — экземпляры одного компонента, а не копии.
- Своего компонента нет в ките — локальный компонент на странице `Components` в секции области (`CRM / KPI card`), с description: что это и почему кита не хватило.

**Зачем.** Экземпляр несёт ключ компонента: генератор и MCP ставят в код `@mdigital/mbank-ui` с нужными props. Detached-копия становится одноразовым div-ом, который расходится с китом при первом обновлении.
**Проверка.** `figma-learn`: использование компонентов по ключу (mapped / partial / missing / local / unknown), detached по имени, локальные компоненты, повторённые 2+ раз → «кандидат в кит»; `structure-audit.js`: `component-inside-screen`, `component-outside-components-page`, `component-no-description`.

## 4. Имена

- Фрейм экрана: `<Поток> / <Экран> / <Состояние> / <ширина>` — `Кредиты / Список заявок / Empty / 1440`. Пока не утверждён — с префиксом `[draft]`.
- Слои — по смыслу: `Sidebar`, `Content`, `Body`, `Header`, `Filters`, `Table card`, `KPI`, `Empty state`; текст — по роли: `Title`, `Amount`, `Status`. Не `Frame 12`, `Group 3`, `Rectangle`.
- Без текста-заглушки: `Title`, `Label`, `Button`, `Lorem`, `Заголовок` в готовом макете — ошибка.

**Зачем.** По имени фрейма `figma-learn` и генератор собирают экран из состояний и ширин, по именам слоёв — узнают блоки (шапка, фильтры, таблица, карточка). `Frame 12` не говорит ничего: экран уходит в «прочее», а в коде появляется `<div className="frame-12">`.
**Проверка.** `structure-audit.js`: `frame-name`, `default-name`, `placeholder-text`; `lint-design.js`: `default-name`; `figma-learn`: доля слоёв с именем по умолчанию и примеры.

## 5. Секции, состояния, Ready for dev

- Каждый экран — в Section `<Область> / <Экран>`; строки — состояния (Default, Loading, Empty, Error, No access), колонки — ширины (1440, 768, 375 / 393). Ничего не лежит на холсте отдельно.
- У списка — минимум Default, Empty и Error; у формы — Error (ошибки полей); у экрана с правами — No access. Тексты пустых состояний говорят, что делать дальше.
- Утвердили — уберите `[draft]` и отметьте секцию **Ready for dev** (Dev Mode → Mark as ready for dev).

**Зачем.** Секция с отметкой — сигнал фронтенду и агентам, что это можно брать в работу; состояния, которых нет в макете, разработчик придумает сам, и design-qa потом найдёт расхождение.
**Проверка.** `structure-audit.js`: `loose-top-level`, `section-junk`, `overlap`; `figma-learn`: состояния по каждому экрану, «списки без пустого состояния», доля Ready for dev и `[draft]`.

## 6. Code Connect

- Компоненты кита, у которых есть код, связаны через Code Connect (карта компонентов design-engine — источник: какой Figma-компонент каким компонентом кода закрыт).
- Новый компонент в ките — сразу описание и связь с кодом, иначе MCP отдаёт «сырую» разметку вместо `<Button variant="primary">`.

**Зачем.** С Code Connect `get_design_context` возвращает готовый импорт и props; без него агент угадывает по картинке.
**Проверка.** `figma-design-system` (раздел Code Connect каталога), `figma-learn`: статус кода по ключу компонента (`code-missing` и `code-partial` в бэклоге).

## Короткий чек-лист перед «Ready for dev»

1. `structure-audit.js` на странице — 0 ошибок.
2. Нет `Frame N` / `Group N`, нет текста-заглушки.
3. Все цвета, отступы, радиусы — переменные; текст — стили.
4. Компоненты кита — экземпляры; detached подписаны и есть в бэклоге.
5. Есть нужные состояния; экран в секции; секция отмечена Ready for dev, `[draft]` убран.
