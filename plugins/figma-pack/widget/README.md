# shadcn Tokens — виджет Figma для токенов shadcn/ui

Виджет живёт прямо на холсте файла: доска токенов shadcn/ui (Tailwind v4, oklch), общая для всей команды (состояние синхронизировано через Figma). Отсюда значения токенов правят, проверяют контраст, записывают в переменные Figma, синхронизируют с сайтом дизайн-системы и выгружают для кода.

**Набор токенов фиксирован.** Это только стандартные токены shadcn/ui со значениями shadcn neutral: 31 цвет (`background`, `foreground`, `card`, `popover`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`, `input`, `ring`, `chart-1…5`, `sidebar-*` и их `*-foreground`) и `radius`. Проект меняет **только значения** этих имён; новые имена не добавляются нигде — ни в окне, ни при импорте, ни при отправке на сайт.

Источник: `plugins/figma-pack/skills/ds-tokens/references/shadcn-tokens.json` (schema `shadcn/tokens@1`), вшивается в виджет при сборке.

Работает в Figma Design и FigJam (в FigJam — доска, правка и выгрузка; запись в переменные только в Figma Design).

> Проверено на имитации Widget API и Plugin API (`test/`). В настоящей Figma эту версию ещё не запускали — первый запуск пришлите скриншотом и отчётом «Применить».

## Поставить (дизайнеру, без сборки)

`dist/` лежит в репозитории, собирать ничего не нужно.

1. Figma Desktop → меню **Widgets** → **Development** → **Import widget from manifest…**
2. Выбрать файл `plugins/figma-pack/widget/manifest.json`.
3. На холсте: **Resources** (Shift+I) → **Widgets** → **Development** → **shadcn Tokens** → перетащить на холст.

Идентификатор виджета в manifest прежний, поэтому уже поставленный виджет обновится на месте.

## Свойства виджета (панель сверху при выделении)

| Кнопка | Что делает |
|---|---|
| Редактировать | окно правки значений |
| Проверить файл | перечитать коллекцию `shadcn` файла, обновить статусы |
| Применить в Figma | окно на вкладке «Figma»: сначала «Что изменится», потом «Применить» |
| Выгрузить для кода | окно на вкладке «Код» |
| Сайт дизайн-системы | окно на вкладке «Сайт»: подключение, «Получить с сайта», «Отправить на сайт» |

На доске: счётчики (токенов, изменено, проблем контраста AA), вкладки групп (фон и текст, акценты, границы, графики, сайдбар, радиус), строки с образцами light / dark, CSS-переменной, переменной Figma и статусом. Клик по строке открывает её в окне.

## Окно

1. **Токены** — все токены, поиск и фильтр по группе. Поле light / dark принимает `oklch(L C H)`, `oklch(L C H / 10%)` или `#hex`; радиус — rem или px (одно значение на обе темы). `↺` возвращает значение shadcn по умолчанию. Контраст AA проверяется для `X-foreground` на `X`, `foreground` и `muted-foreground` на `background` (и `muted-foreground` на `muted` с порогом 3).
2. **Код** — выгрузка и загрузка (ниже).
3. **Figma** — проверка и запись в переменные.
4. **Сайт** — синхронизация с сайтом дизайн-системы.

## Применить в Figma

- Пишет в коллекцию `shadcn` с режимами **Light / Dark**. Имена переменных — как CSS-переменные shadcn (`background`, `primary`, `chart-1`, `sidebar-primary-foreground`…), плюс `radius` (FLOAT, px). Нет коллекции или режима Dark — создаются; всё созданное есть в отчёте. Ничего не удаляется.
- Значения — цвет Figma, переведённый из oklch (OKLab → sRGB, точная формула CSS Color 4; прозрачность `oklch(1 0 0 / 10%)` сохраняется как альфа). Цвета за пределами sRGB обрезаются по каналам, как в браузере.
- Scopes: фоны — заливки (`FRAME_FILL`, `SHAPE_FILL`), `*-foreground` — `TEXT_FILL`, `border` / `input` / `ring` (и `sidebar-border` / `sidebar-ring`) — `STROKE_COLOR` (`input` ещё и заливка), `destructive` — заливка, текст и обводка, `chart-*` — заливка и обводка, `radius` — `CORNER_RADIUS`. Code syntax — `var(--имя)`.
- По умолчанию пишет изменённые токены и те, что в файле расходятся или отсутствуют (по последней проверке); галочка «все токены» — для пустого файла.
- «Что изменится (без записи)» показывает тот же отчёт, ничего не меняя.
- Тариф с одним режимом переменных: записывается только Light, в отчёте одна строка об ограничении.
- Если файл подключает коллекцию `shadcn` из библиотеки, «Применить» отказывает (иначе появилась бы локальная копия): меняйте значения в файле библиотеки. Пробный прогон доступен везде.

## Выгрузить для кода

Вкладка «Код» → «Скачать»:

| Файл | Для чего |
|---|---|
| `shadcn-tokens.json` | тот же формат `shadcn/tokens@1`, что и источник, с изменёнными значениями |
| `tokens.css` | тема Tailwind v4 + shadcn/ui: `@theme inline`, `:root`, `.dark`, `@layer base` — заменяет тему в `globals.css` |
| `shadcn-theme.json` | shadcn `registry:theme` — для `npx shadcn@latest add ./shadcn-theme.json` |

Значения по умолчанию всей дизайн-системы меняются только с согласия владельца: `shadcn-tokens.json` → `plugins/figma-pack/skills/ds-tokens/references/shadcn-tokens.json`, затем `node plugins/design-engine/scripts/sync-contracts.mjs` и `npm test`.

**Загрузить**: вставить `shadcn-tokens.json` → отличия от значений по умолчанию становятся правками доски (текущие правки заменяются). Незнакомые имена не добавляются — окно их перечисляет.

## Сайт дизайн-системы (вкладка «Сайт»)

Источник значений проекта — сайт `apps/ds-configurator` (локально `http://localhost:8797`, API `/api/projects`). Сайт в Figma не пишет: виджет сам берёт значения по HTTP и пишет их через Plugin API.

1. Адрес сайта, идентификатор проекта, ключ записи (сайт → проект → Figma → «Копировать»). Адрес и проект хранятся в файле (plugin data документа), ключ — только у пользователя (`clientStorage`).
2. **«Получить с сайта»** создаёт или обновляет коллекцию `shadcn` (Light, Dark) по `figma.json` проекта: значения oklch / hex → цвет Figma с альфой, радиус → px, ссылки на другие переменные `shadcn` (например `ring` → `primary`) — алиасы. Повторное получение меняет те же переменные на месте; лишние переменные не удаляются и на сайт не уходят.
3. **«Отправить на сайт»**: значения, отличные от базы, уходят правками (`overrides`, цвет в `oklch()`, радиус в px, ссылка — `var(--имя)`). Переменные с именами не из набора shadcn не отправляются (в отчёте). Запрос несёт версию, от которой получены значения (`If-Match`); если на сайте новее — **конфликт**, ничего не записано.
4. Статус: `совпадает` / `на сайте новее` / `в Figma новее` / `конфликт`. При неотправленных правках «Получить» отказывает; «Получить с перезаписью» берёт версию сайта.

`networkAccess` разрешает `http://localhost:8797` и заглушку прод-домена `https://ds.example.mdigital.kg` — замените её на настоящий домен сайта.

## Разработчику

```
widget/
  manifest.json        containsWidget, editorType figma + figjam, permissions teamlibrary
  core/                чистая логика (node:test): oklch (цвет), model, checks, sync, exports, io, site
  src/code.jsx         виджет: useSyncedState / useSyncedMap / usePropertyMenu
  src/board.jsx        доска на холсте
  src/actions.js       действия меню и окна; src/figma-io.js — чтение и запись коллекции shadcn
  src/site-actions.js  сайт: подключение, получить / отправить; src/site-io.js — запись figma.json в shadcn
  src/ui/              окно (обычный HTML/JS), цвета окна — роли shadcn, вшиваются при сборке
  scripts/build.mjs    esbuild → dist/code.js + dist/ui.html
  test/                oklch, core, widget, site, mode-limit (dist/code.js на builder/test/figma-mock.mjs)
```

После изменения `shadcn-tokens.json` или кода пересоберите `dist`:

```bash
cd plugins/figma-pack/widget && npm install && npm run build   # esbuild; node_modules не коммитить
node --test plugins/figma-pack/widget/test/*.test.mjs           # из корня
```

## История

До 2026-11-11 виджет назывался «Mbank Tokens» и работал со слоем токенов Mbank (коллекции Foundation, бренды, токены проекта, вкладка «Компоненты»). По решению от 2026-11-11 этот слой удалён из всей дизайн-системы: остался только стандартный набор shadcn/ui. Компоненты из контрактов собирает DS Builder.
