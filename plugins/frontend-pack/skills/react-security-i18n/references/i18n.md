# i18n: setup and checks

## Files

```
src/shared/config/
  i18n.ts                       # the single i18next instance
  i18next.d.ts                  # typed keys
  locales/
    ru/common.json  ru/errors.json  ru/orders.json   # source of truth
    ky/common.json  ...
    en/common.json  ...
src/shared/lib/format.ts        # Intl helpers
scripts/check-i18n.mjs          # CI: ru plural completeness, missing keys per language
```

Small apps may keep all keys in one `common` namespace per language; split by feature when a file passes ~300 keys.

## i18n.ts (Vite SPA)

```ts
import i18next from 'i18next'
import { initReactI18next } from 'react-i18next'
import ruCommon from './locales/ru/common.json'
import ruErrors from './locales/ru/errors.json'
import kyCommon from './locales/ky/common.json'
import kyErrors from './locales/ky/errors.json'
import enCommon from './locales/en/common.json'
import enErrors from './locales/en/errors.json'

export const SUPPORTED_LANGUAGES = ['ru', 'ky', 'en'] as const
export type Language = (typeof SUPPORTED_LANGUAGES)[number]

export const resources = {
  ru: { common: ruCommon, errors: ruErrors },
  ky: { common: kyCommon, errors: kyErrors },
  en: { common: enCommon, errors: enErrors },
} as const

export const i18n = i18next.createInstance()

void i18n.use(initReactI18next).init({
  resources,
  lng: readSavedLanguage() ?? 'ru',
  fallbackLng: 'ru',
  supportedLngs: SUPPORTED_LANGUAGES,
  defaultNS: 'common',
  ns: ['common', 'errors'],
  interpolation: { escapeValue: false }, // React already escapes
  returnNull: false,
})

i18n.on('languageChanged', (lng) => {
  document.documentElement.lang = lng
})

function readSavedLanguage(): Language | undefined {
  try {
    const saved = localStorage.getItem('mdigital.lang')
    return SUPPORTED_LANGUAGES.find((l) => l === saved)
  } catch {
    return undefined // storage blocked (private mode): use the default
  }
}
```

- Import `@/shared/config/i18n` once in `src/main.tsx` before rendering. `getUserMessage` (owned by `react-error-handling`) imports the same instance.
- Large apps: lazy-load non-default languages with dynamic `import()` per language and `i18n.addResourceBundle`; keep `ru` bundled so the first paint never waits.
- Switching language: `i18n.changeLanguage(lng)` and save to `localStorage` (a UI preference, allowed).

## Next.js App Router

- Client components: a `'use client'` provider in the root layout initializes the same config and wraps children in `I18nextProvider`; components use `useTranslation`.
- Server components: create a **per-request** instance (`i18next.createInstance()` + same `resources`, `lng` from the route segment or cookie) and call its `t`; never mutate a shared module singleton on the server.
- `<html lang={lng}>` is rendered by the root layout from the same value.

## Typed keys

```ts
// src/shared/config/i18next.d.ts
import 'i18next'
import type { resources } from './i18n'

declare module 'i18next' {
  interface CustomTypeOptions {
    defaultNS: 'common'
    resources: (typeof resources)['ru'] // ru is the source of truth
  }
}
```

A wrong key is now a type error: `t('orders.craete')` fails `tsc`. Interpolation and plural keys are typed from the JSON (`resolveJsonModule: true`). Recent i18next versions also offer a selector API (`t(($) => $.orders.create)`) enabled in `CustomTypeOptions`; adopt it only after checking the installed i18next and react-i18next changelogs.

## Plural example (ru, ky, en)

```json
// ru/orders.json
{ "count_zero": "Нет заказов", "count_one": "{{count}} заказ", "count_few": "{{count}} заказа", "count_many": "{{count}} заказов", "count_other": "{{count}} заказа" }
// en/orders.json
{ "count_zero": "No orders", "count_one": "{{count}} order", "count_other": "{{count}} orders" }
// ky/orders.json - CLDR gives ky the categories one and other
{ "count_one": "...", "count_other": "..." }
```

```tsx
t('orders:count', { count: total })
```

Translations for `ky` come from a translator, not from the developer or the model; leave the key missing (falls back to `ru`) rather than inventing text.

Expo / React Native (Hermes) needs an `Intl.PluralRules` polyfill; without it only `_one`/`_other` work. Not relevant for web.

## scripts/check-i18n.mjs (CI)

```js
#!/usr/bin/env node
// Fails when a ru plural key lacks a CLDR category, or ky/en has keys that ru does not.
import { readdirSync, readFileSync } from 'node:fs'
import { join } from 'node:path'

const DIR = 'src/shared/config/locales'
const RU_PLURALS = ['one', 'few', 'many', 'other']
const flat = (obj, prefix = '') =>
  Object.entries(obj).flatMap(([k, v]) => (v && typeof v === 'object' ? flat(v, `${prefix}${k}.`) : [`${prefix}${k}`]))
const load = (lng) =>
  Object.fromEntries(readdirSync(join(DIR, lng)).map((f) => [f.replace('.json', ''), flat(JSON.parse(readFileSync(join(DIR, lng, f), 'utf8')))]))

const problems = []
const ru = load('ru')
for (const [ns, keys] of Object.entries(ru)) {
  const bases = new Set(keys.filter((k) => /_(zero|one|few|many|other)$/.test(k)).map((k) => k.replace(/_(zero|one|few|many|other)$/, '')))
  for (const base of bases)
    for (const cat of RU_PLURALS) if (!keys.includes(`${base}_${cat}`)) problems.push(`ru/${ns}: ${base}_${cat} missing`)
}
for (const lng of ['ky', 'en']) {
  for (const [ns, keys] of Object.entries(load(lng))) {
    const ruKeys = new Set((ru[ns] ?? []).map((k) => k.replace(/_(zero|one|few|many|other)$/, '')))
    for (const k of keys) if (!ruKeys.has(k.replace(/_(zero|one|few|many|other)$/, ''))) problems.push(`${lng}/${ns}: ${k} not in ru`)
  }
}
if (problems.length) { console.error(problems.join('\n')); process.exit(1) }
```

Add `"check:i18n": "node scripts/check-i18n.mjs"` to the project's scripts and run it in CI next to lint. Missing `ky`/`en` translations are reported by the translation workflow, not by CI (they fall back to `ru`).

## format.ts

```ts
// src/shared/lib/format.ts
import { i18n } from '@/shared/config/i18n'

const locale = () => i18n.language || 'ru'

export const formatDate = (iso: string, options: Intl.DateTimeFormatOptions = { dateStyle: 'medium' }) =>
  new Intl.DateTimeFormat(locale(), options).format(new Date(iso))

export const formatNumber = (value: number, options?: Intl.NumberFormatOptions) =>
  new Intl.NumberFormat(locale(), options).format(value)

export const formatMoney = (amount: number, currency: 'KGS' | 'RUB' | 'USD' = 'KGS') =>
  new Intl.NumberFormat(locale(), { style: 'currency', currency }).format(amount)

export const formatRelative = (value: number, unit: Intl.RelativeTimeFormatUnit) =>
  new Intl.RelativeTimeFormat(locale(), { numeric: 'auto' }).format(value, unit)
```

The exact currency symbol and grouping come from the runtime's CLDR data and can differ between browsers; tests assert with the same helper, not with a hard-coded string. Cache `Intl` formatters per locale if profiling shows them in a hot path.
