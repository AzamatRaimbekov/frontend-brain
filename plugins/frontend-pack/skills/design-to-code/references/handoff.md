# Передача между этапами

Каждый этап получает на вход только артефакты, перечисленные здесь. Нет артефакта — этап не начинается, `design-lead` возвращает задачу назад.

## 1. Бриф → черновик (этапы 1 → 2)

- Утверждённый бриф в формате `figma-brief` (web — формат `react-page-ux` §1, mobile и сайты — `figma-design/references/briefs.md`).
- Целевой файл Figma (`fileKey`) и страница; каталог (`.figma/design-system.json` или Mbank-каталог из `mbank-design-system`).
- Для web/CRM на Mbank: явный ответ пользователя «рисуем черновик на Inter» или «ждём Inter Mbank» (G03).

## 2. Черновик → утверждение (этапы 2 → 3)

Отчёт `figma-designer` в формате `figma-design` §7: ссылки на каждый фрейм `https://www.figma.com/design/<fileKey>/?node-id=<id-через-дефис>`, числа `structure-audit.js` и `lint-design.js`, пробелы на странице Proposals, допущения. Это сообщение передаётся дизайнеру как есть.

## 3. Утверждение → спека (этапы 3 → 4)

- Ссылка на утверждённый фрейм или Section с `node-id`.
- Ответ дизайнера: «утверждено, Ready for dev», или список правок (тогда назад на этап 2 или дизайнер правит сам).
- `design-lead` проверяет через `get_metadata`, что в именах фреймов нет `[draft]`.

## 4. Спека → UX.md, план, код (этапы 4 → 5, 6, 7)

Вызов `figma-reader`: ссылка, корень проекта, фича или маршрут, `Target platforms: web`. Результат сохранить в `.figma/<fileKey>/<nodeId>-spec.md` (папка `.figma/<fileKey>/` в `.gitignore`, спеку в PR передаём ссылкой на фрейм и текстом ключевых разделов). В `UX.md`:

- раздел 8 спеки «Missing in design» → строки «Состояния» и «Адаптив» с явными допущениями;
- раздел 11 спеки (вопросы) → «Допущения» или вопрос дизайнеру;
- раздел 9 (несовпадения токенов) решается до кода по политике `figma-to-react` §3.

## 5. Код → сверка, ревью (этапы 7 → 8, 9)

- Запущенный dev-сервер и URL страницы; данные из MSW, совпадающие с примером в макете.
- Путь к спеке и к скриншотам Figma.
- Список изменённых файлов (`git diff --name-only`).

## 6. Описание PR (этап 10)

```
## Что сделано
<страница / компонент>, маршрут <path>

## Дизайн
Figma: <ссылка на утверждённый фрейм> (утвердил: <дизайнер>, дата)
Спека: .figma/<fileKey>/<nodeId>-spec.md (ключевые решения ниже)
UX.md: src/pages/<route>/UX.md

## План файлов
<дерево от frontend-architect>

## Сверка с Figma (design-qa)
| Элемент | Figma | У нас | Решение |
|---|---|---|---|

## Ревью (frontend-reviewer)
Блокирующих: 0. Остальное: <список или «нет»>

## Проверено
- [ ] 1280 / 768 / 375, без горизонтального скролла на 375
- [ ] загрузка, пусто, ошибка, 422 на форме (MSW)
- [ ] клавиатура, консоль без ошибок
- [ ] файлы ≤ 150 строк

## Допущения и пробелы дизайн-системы
<список; пробелы — для дизайнеров>
```
