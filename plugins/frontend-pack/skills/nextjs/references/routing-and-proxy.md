# Routing, route handlers and proxy

Verified against Next.js 16.4.3 (2026-10-25).

## Folder layout with `src/`

```
src/
  app/                      routing only: page.tsx, layout.tsx, loading.tsx, error.tsx, not-found.tsx, route.ts
    (marketing)/            route group: own layout, no URL segment
    (dashboard)/orders/[id]/page.tsx
    api/webhooks/cms/route.ts
    providers.tsx           'use client' providers
  features/ shared/          per react-architecture
  proxy.ts                  next to app/ (src/proxy.ts when src/ is used)
  instrumentation.ts        server startup hooks, onRequestError
```

- Pages and layouts are thin: read `params`/`searchParams`, render a feature component.
- Typed routes helpers: `PageProps<'/orders/[id]'>`, `LayoutProps<'/orders'>` (generated by `next dev`/`next build`
  or `npx next typegen`). `params` and `searchParams` are Promises (sync access removed in 16).
- Parallel routes need a `default.tsx` in every slot since 16.
- URL state (filters, tabs, pagination): `nuqs` (`react-architecture`).

## Route handlers

```ts
// src/app/api/webhooks/cms/route.ts
import { revalidateTag } from 'next/cache'
import { timingSafeEqual } from 'node:crypto'
import { z } from 'zod'

const bodySchema = z.object({ tag: z.enum(['posts', 'pages']) })

export async function POST(request: Request) {
  const secret = Buffer.from(request.headers.get('x-webhook-secret') ?? '')
  const expected = Buffer.from(process.env.CMS_WEBHOOK_SECRET ?? '')
  if (secret.length !== expected.length || !timingSafeEqual(secret, expected)) {
    return Response.json({ code: 'unauthorized', title: 'Unauthorized' }, { status: 401 })
  }
  const parsed = bodySchema.safeParse(await request.json().catch(() => null))
  if (!parsed.success) return Response.json({ code: 'invalid_body', title: 'Invalid body' }, { status: 400 })
  revalidateTag(parsed.data.tag, 'max')
  return new Response(null, { status: 204 })
}
```

- Use route handlers for webhooks, other clients (mobile, partners), downloads/streams, and a BFF that keeps
  tokens server-side. UI mutations from this app are Server Actions.
- Error responses: Problem Details JSON with a stable `code` (`react-error-handling`).
- Same auth rules as actions: check the session/secret inside the handler.
- With Cache Components a `GET` handler that reads no runtime data is prerendered; add `await connection()` or read
  `request` headers to keep it per-request.

## Proxy (`proxy.ts`, formerly `middleware.ts`)

```ts
// src/proxy.ts
import { NextResponse, type NextRequest } from 'next/server'

const PUBLIC = ['/login', '/forgot-password']

export function proxy(request: NextRequest) {
  const hasSession = request.cookies.has('session') // optimistic: presence only, real check in the DAL
  const isPublic = PUBLIC.some((p) => request.nextUrl.pathname.startsWith(p))
  if (!hasSession && !isPublic) {
    const url = new URL('/login', request.url)
    url.searchParams.set('next', request.nextUrl.pathname)
    return NextResponse.redirect(url)
  }
  return NextResponse.next()
}

export const config = {
  // skip static files, images and metadata files
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico|sitemap.xml|robots.txt).*)'],
}
```

- One `proxy.ts` per project; split logic into modules and import them.
- Runs on Node.js; the `runtime` option throws. `fetch` cache options do nothing here.
- Good for: optimistic auth redirects, locale redirects, A/B rewrites, CSP nonce and other headers.
- Not for: authorization decisions (repeat them in DAL/actions/handlers), slow data fetching, static redirects
  (use `redirects()` in `next.config`).
- Migration from `middleware.ts`: `npx @next/codemod@latest middleware-to-proxy .` (renames the file and the export;
  `skipMiddlewareUrlNormalize` → `skipProxyUrlNormalize`).

## Navigation

- `<Link>` prefetches automatically in production. With Partial Prefetching (16.3+, part of Cache Components) the
  shared App Shell is prefetched; `prefetch={true}` adds more of the target page.
- Server-side redirects: `redirect()` / `permanentRedirect()` from `next/navigation`; client: `useRouter().push`.
- `notFound()` for expected 404s; `forbidden()`/`unauthorized()` need `experimental.authInterrupts`.
